# Quy tắc database Aurum

NestJS là backend duy nhất truy cập database nghiệp vụ qua Prisma. Một chức năng chỉ được xem là hoàn thiện khi có schema/migration, validation, authorization company/branch phía server, persistence, API, kiểm thử và UI phù hợp. Không hard-code KPI hoặc tuyên bố CRUD nếu không lưu dữ liệu. Thay đổi schema phải kiểm thử trên database test trước và đánh giá backup/rollout trước khi áp vào development/production.

Seed development phải chạy chủ động, kiểm tra môi trường, tài khoản, quyền và database sau kết nối; không update, xóa hoặc ghi đè dữ liệu khác. Script development hiện chỉ áp dụng cho development local được cho phép; không hỗ trợ production. Production DEMO tenant là mục tiêu riêng, chỉ được provision sau 12 mục owner policy và xác nhận cụ thể. Không có lệnh DROP, TRUNCATE hoặc reset mặc định. Thao tác phá hủy cần xác nhận riêng. Không commit secrets, dữ liệu khách hàng; không dùng tài khoản quản trị cho ứng dụng và không đưa credentials vào frontend.

Tính năng login, authorization, API company và dashboard dữ liệu vẫn chưa hoàn thiện. Không mở dữ liệu riêng tư trước khi xác thực và phân quyền được thực thi và kiểm thử.

## Batch 08 grant ordering
The runtime table-level grants in `DEVELOPMENT-RUNTIME-GRANTS.sql` are for after the tables exist. MySQL requires CREATE privilege when granting rights on a non-existent table; granting CREATE to runtime merely to pre-grant rights would violate least privilege. User requested rights before migration, so request clarification on migration-first / DBA-grant-second sequence rather than silently changing order. See MySQL reference: https://dev.mysql.com/doc/refman/8.4/en/grant.html . Never grant global privileges, GRANT OPTION or classification writes to runtime. This is an ordering issue; backup/recovery and development provisioner safety remain independent prerequisites.
