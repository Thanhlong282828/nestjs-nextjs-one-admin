# Local performance budgets (provisional)

`scripts/performance-lab.mjs` asserts encoded JS <= 350,000 bytes and CSS <= 100,000 bytes, separately for initial admin and storefront routes, using same-origin entries in a cache-disabled local production Chrome run. These conservative guardrails have headroom over the first observed local samples (~143 kB JS/8.5 kB CSS admin; ~136 kB JS/2.9 kB CSS storefront). They are not product SLOs, do not include HTML, fonts or third-party transfers and require revision after observing real production workload. The script requires HRM navigation to request a separate JS resource. Missing resource timing fails; do not silently treat missing entries as zero.

LCP <= 2.5s, INP <= 200ms and CLS <= 0.1 are reference thresholds for field evaluation, not guarantees from this local lab. INP and RUM are not measured. The existing 3s LCP and summed non-input shifts are diagnostic samples, not a full Lighthouse or Core Web Vitals assessment. First-party privacy-reviewed RUM, p75 by device/network and controlled throttled profiling are needed before enforcing field budgets. No production telemetry or image provider is configured by this document.
