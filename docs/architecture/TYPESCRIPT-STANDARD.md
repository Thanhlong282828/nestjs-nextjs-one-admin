# Aurum — TypeScript-first engineering standard v1.0

Mandatory for future NestJS/Next.js applications, domain, CQRS, repositories/Prisma, DTOs, validation, guards, React, hooks, contracts and business logic. Use `.ts`/`.tsx` by default; `.mts` may be used where module tooling requires it. Do not introduce JavaScript business logic. TypeScript is not a security or runtime validation boundary: parse and validate untrusted input using the approved library/validator, narrow `unknown`, avoid `any`/unsafe assertions/non-null assertions, use discriminated unions, generics, readonly and explicit public API return types where appropriate. Preserve tenant/company/branch context, decimal currency and timezone semantics end-to-end. Generated Prisma types alone do not authorize access or validate client payloads. Define API contracts from authoritative server schemas/types with runtime validation rather than hand-fabricating incompatible frontend types. Follow connected-data governance, Module Library + CQRS + MVC and production owner policy.

## Exceptions and enforcement

JavaScript may remain only where technically justified for build/tooling, migration utilities, browser automation, package utilities, third-party config or a temporary compatibility bridge; no business logic duplication. Prefer TypeScript where supported. `scripts/typescript-policy/exceptions.json` is an **exact path allowlist** for existing workspace test/database tooling exceptions with reasons. New JS in `apps` or `packages` fails `npm run test:typescript-policy` unless it is an explicitly reviewed legacy test or `apps/api/scripts` tooling entry with a nonempty reason; the checker refuses an exception for source application paths. New tests should use TS when supported. Root `scripts/`, Playwright/ESLint config are tooling and outside this workspace application gate; their JavaScript requires a technical rationale and review. Generated Prisma client, framework output, `node_modules`, root workspace build outputs are excluded; source code nested in a directory merely named `dist` is not excluded. Symlinks in scanned workspace are rejected except ignored vendor paths. The gate checks extensions and paths, not semantic behavior, external workspaces, root tooling content, dynamic imports or generated code; reviewers must check those independently. Typecheck, ESLint, architecture tests and build remain separate checks. CI quality workflow runs the gate; actual GitHub workflow execution is not claimed without evidence.

## Initial audit and migration

Initial inventory (excluding generated, vendor, dist and .next) found 51 TS/TSX/MTS and 45 JS/MJS/JSX files across repository; counts describe the snapshot before this checkpoint's additions/migration. Application sources under `apps/*/app`, `apps/api/src` and `packages/*/src` contained no JavaScript; no application business JS was converted or deleted. Existing `.mjs` under `apps/api/scripts` implement safety-critical local database guards/seed tooling and are intentionally retained until separately reviewed/tested migration. Existing `.mjs` under workspace `test/` are legacy tests/support; migrate incrementally without lowering coverage or test isolation. Root `scripts/*.mjs` are automation, browser QA or enforcement tooling; `eslint.config.mjs` is tooling configuration. `next-env.d.ts`, generated Prisma client, `.next`, `dist` and `node_modules` are generated/vendor and must not be edited as application source. A single i18n test suite was migrated to TS, strict typechecked and run against the built package before removing its old `.mjs`; all five behavioral tests retained. Its workspace test script explicitly runs `tsc -p tsconfig.test.json` then Node with `tsx`.

## Review and verification

Run `npm run test:typescript-policy`, `npm run lint`, `npm run test:architecture`, `npm run typecheck`, workspace tests/integration tests on isolated test databases, and `npm run build`. Audit imports/exports, runtime behavior and test/build before removing an obsolete legacy JS file. Preserve uncommitted work and do not migrate database targets or data as part of language conversion. An exact allowlist change must include the file's rationale and review; do not use it to exempt app/business JS. Record actual pass/fail/skip and unresolved migration in progress/handoff.
